# Thunderbird Background add-ons

English | [简体中文](README.zh_CN.md)

## Introduction

Thunderbird Background add-ons is a Thunderbird extension for background operation. It uses a local Linux tray companion to hide and show windows, or quit Thunderbird.

The project combines a Thunderbird Experiment extension with a Python/Gio Native Messaging host. Installation is per-user and does not require root privileges.

## Requirements and Compatibility

| Component | Requirement |
| --- | --- |
| Thunderbird | Native Linux installation, version **156.0 or later** |
| Python | System Python 3; installed helper scripts use `/usr/bin/python3` |
| Python bindings | PyGObject with Gio/GLib; X11 startup-notification handling also uses Gdk 3 |
| Desktop tray | A StatusNotifierWatcher; GNOME requires an enabled AppIndicator/StatusNotifier extension |
| Development tests | Node.js for window tests; Python and PyGObject for Python tests |

The primary target is **GNOME Wayland**. Flatpak and Snap installations are not supported. The silent-start launcher and runtime tests invoke `/usr/bin/thunderbird` directly.

The manifest permits Thunderbird `156.0` and later without an upper version limit. This permits installation, not a guarantee of compatibility with every future release: the extension uses internal Experiment APIs that may change.

> [!NOTE]
>
> In principle, this extension may also be applicable to versions of Thunderbird prior to 156.0. However, due to limitations in the development environment, these environments have not yet been tested.

## Installation

1. Install the PyGObject bindings (`python-gobject` or your distribution's equivalent).

   - Debian / Ubuntu

     ```bash
     sudo apt install python3-gi python3-gi-cairo gir1.2-gtk-4.0
     ```

   - Red Hat / CentOS

     ```bash
     sudo yum install python3X-gobject.x86_64
     ```

     > [!NOTE]
     >
     > Check your system's Python version and replace `X` with the appropriate version component.

   - Fedora

     ```bash
     sudo dnf install python3-gobject
     ```

   - Arch Linux

     ```bash
     sudo pacman -S python-gobject
     ```

2. On GNOME, install the **AppIndicator and KStatusNotifierItem Support** extension.

3. From the project directory, run:

   ```bash
   python3 install.py
   ```

4. In Thunderbird, open **Add-ons and Themes → gear icon → Install Add-on From File** and select the XPI generated by the installer. For the current manifest version, the path is:

   ```text
   dist/thunderbird-background-1.0.1.xpi
   ```

5. Accept the permissions and confirm that the tray icon appears. Test closing and restoring the last mail window before relying on background operation.

The installer automatically builds the XPI, copies the helper scripts, registers the Native Messaging host, and creates user-level desktop entries.

### Permissions and Privacy

Thunderbird requests **full, unrestricted access to Thunderbird and your computer** because Experiment APIs control native windows and intercept close requests. This is a powerful permission; review the source code before installing.

## Usage

| Action | Result |
| --- | --- |
| Close the last main mail window | Hide to tray, or minimize if the tray is unavailable |
| Press **Ctrl+Q** in a main mail window | Hide that window to the background, or minimize if the tray is unavailable |
| Click the tray icon or choose **Show Thunderbird** | Restore the window |
| Choose **Hide to Background** | Hide main mail windows while the tray is available |
| Choose **Quit Thunderbird** | Request a normal shutdown, preserving draft confirmation |
| Click the application launcher | Restore a connected instance, or start Thunderbird normally |
| Click a notification that opens a message in the main window | Restore the target main mail window, then let Thunderbird open the message |

**Ctrl+Q** is redirected only in main mail windows; compose windows are unchanged. To exit Thunderbird, use its **Quit** menu item or **Quit Thunderbird** in the tray menu. These commands preserve the normal draft confirmation flow.

Notification action buttons such as **Mark as Read** and **Delete** retain their existing behavior. Notifications still depend on your Thunderbird account preferences and desktop notification settings.

With default installation paths, you can also send commands from a terminal:

```bash
~/.local/share/thunderbird-background/host.py --show
~/.local/share/thunderbird-background/host.py --hide
~/.local/share/thunderbird-background/host.py --quit
```

These commands target **all connected instances**. Each tray menu controls only its own Thunderbird instance.

> [!NOTE]
>
> The tray icon does not show an unread count.
>
> Background operation cannot retrieve mail while the computer is shut down, logged out, or asleep.

### Desktop Integration

When an original desktop entry is available, the installer creates a user-level override for `org.mozilla.Thunderbird.desktop`. Ordinary clicks go through `show.py`, which first restores an existing background instance and starts Thunderbird normally if none is available. Explicit arguments, including `mailto:` links, message files, and compose commands, are forwarded to Thunderbird.

The original desktop entry's name, translations, icon, file associations, and actions are preserved. System files under `/usr/share/applications/` are not changed. An existing user entry with the same name is backed up before replacement and restored on uninstall. If you later replace the entry manually, uninstallation leaves that replacement untouched.

## Optional Login Autostart

Login autostart is **not enabled by the installer**. To opt in, create `~/.config/autostart/thunderbird-background.desktop` with the following content:

```ini
[Desktop Entry]
Type=Application
Name=Thunderbird Background
Exec=/home/YOUR_USER/.local/share/thunderbird-background/autostart.py
Terminal=false
StartupNotify=false
```

Replace the `Exec` value with the **absolute path** to your installed `autostart.py`. Desktop entries do not expand `~` or shell variables. Quote the path if it contains spaces. If `XDG_CONFIG_HOME` is set, use its `autostart` directory instead of `~/.config/autostart`.

The launcher sets `THUNDERBIRD_BACKGROUND_AUTOSTART=1` and starts Thunderbird normally. The extension initializes the hidden mail window and keeps it hidden once the tray is ready. If the tray is still unavailable after 15 seconds, startup falls back to a minimized window. Restoring the window cancels pending automatic hiding.

Manual launches do not set this variable and display windows normally. Login startup output is appended to `~/.cache/thunderbird-background/autostart.log` by default. Remove the autostart desktop entry to disable login startup.

## Updating

After updating the source, rerun `python3 install.py` to refresh the native scripts and desktop integration, then install the newly built XPI through Thunderbird.

For an **extension-only** update when the installed companion is still suitable, run:

```sh
python3 install.py --build-only
```

Install the resulting XPI through **Install Add-on From File**. Building alone does not update the installed extension or companion.

`update_installed.py` is an advanced local maintenance tool, not the recommended installation path. It requires an explicit profile and package, requests a normal Thunderbird shutdown, backs up and directly updates this extension's profile registration and startup-cache entry, then restarts Thunderbird. It requires the system LZ4 library and refuses permission changes or a disabled extension. Review the script and run `python3 update_installed.py --help` before using it with a real profile.

## Troubleshooting

- **No tray icon:** verify that PyGObject is available to `/usr/bin/python3`, your desktop's tray support is enabled, and both the XPI and native companion are installed. Without a working tray, closing the last mail window should minimize it.
- **Cannot find a hidden window:** try the installed **Thunderbird Background** application entry or run `host.py --show` using the path above.
- **Dock click does not restore:** rerun the installer and check that the pinned launcher uses `org.mozilla.Thunderbird.desktop`. If no original entry is found, use the separate **Thunderbird Background** entry.
- **Login startup fails:** check the absolute `Exec` path and `autostart.log`. Do not substitute Thunderbird's `-silent` flag for the supplied launcher.
- **No new-mail notifications:** check Thunderbird's account settings and your desktop's notification permissions. This extension does not enable notifications or automatic mail retrieval.
- **Problems after upgrading Thunderbird:** internal APIs may have changed even if the manifest allows the new version. Disable the extension and verify compatibility before relying on it again.

Paths in this document assume default XDG directories. The installer honors `XDG_DATA_HOME` for the companion and application entries, and `XDG_CONFIG_HOME` for the configuration-side Native Messaging manifest. Logs and command sockets honor `XDG_CACHE_HOME`.

## Development and Testing

Before running static type checks, create a development environment that reuses the system PyGObject installation:

```sh
python3 -m venv --system-site-packages .venv
.venv/bin/python -m pip install --no-cache-dir -r requirements-dev.txt
.venv/bin/basedpyright --pythonpath .venv/bin/python --level error
```

Select `.venv/bin/python` as your editor's Python toolchain as well. The development dependencies include official PyGObject stubs configured for Gdk 3/Gtk 3, matching the launcher. The `--no-cache-dir` option avoids reusing a stub wheel built for a different API version. GI generates repository modules dynamically, so only the missing-source diagnostic is suppressed on those import lines; their types are still checked. The checker retains its default rules; `--level error` displays errors only, while omitting it also reports stricter annotation warnings.

Run the automated tests from the project directory:

```sh
node tests/window.test.cjs
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 install.py --build-only
```

Tests cover window interception and recovery, startup fallbacks, notification restoration, Native Messaging framing, DBusMenu serialization, launcher arguments, desktop-entry preservation, and startup-notification completion. Desktop-facing unit tests use test doubles.

To run runtime checks against an installed Thunderbird binary using a disposable local-only profile:

```sh
python3 tests/runtime_startup.py
TBBG_TEST_NOTIFICATION=1 python3 tests/runtime_startup.py
TBBG_TEST_QUIT_SHORTCUT=1 python3 tests/runtime_startup.py
```

Runtime checks launch headless Thunderbird to verify both initial startup and subsequent startup with the extension already registered. The notification test invokes Thunderbird's actual mail-notification callback with synthetic local mail; it does not send a desktop notification. The shortcut test synthesizes trusted **Ctrl+Q** input, checks hiding and minimization, verifies that menu Quit remains available, and confirms shortcut restoration on cleanup. These tests do not use real accounts or mail, and do not verify visible desktop interactions.

### Project Layout

| Path | Purpose |
| --- | --- |
| `addon/` | Extension manifest, background script, and Experiment API |
| `native/host.py` | StatusNotifierItem/DBusMenu tray and Native Messaging host |
| `native/show.py` | Restore-or-launch entry point and startup-notification handling |
| `native/autostart.py` | Silent login-start launcher |
| `install.py` | Per-user installation, XPI packaging, and uninstallation |
| `update_installed.py` | Advanced update tool for an existing profile |
| `tests/` | Unit tests and disposable-profile runtime checks |
| `dist/` | Generated XPI packages |

## Uninstallation

1. Disable or remove **Thunderbird Background** in Thunderbird so hidden windows can be restored.

2. From the project directory, run:

   ```sh
   python3 install.py --uninstall
   ```

Uninstallation removes the companion scripts, both Native Messaging manifests, the added application entry, and this project's login autostart entry. For a Dock override still managed by this project, it removes the override or restores the original user entry, as appropriate. Source files, generated XPI packages, logs, and other backups are retained.
